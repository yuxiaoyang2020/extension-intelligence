Methodology

This page honestly explains how every metric we show is actually calculated — not marketing copy, but the calculation logic that actually runs in our code.

Data collection

We take one snapshot of the Chrome Web Store's public pages every day, recording each extension's user count, rating, review count, category rank, and overall rank for that day. All historical trends and growth rates are calculated from these daily snapshots as a time series — not sampled estimates.

Growth rate / growth amount

"N-day growth amount" = today's user count − user count N days ago. "N-day growth rate" = growth amount ÷ user count N days ago. If an extension doesn't have N days of history in our database yet (for example, it recently appeared in our tracking for the first time), the corresponding N-day metric is left blank rather than filled with 0 or an estimate — a blank value means "not enough data to calculate," not "no change."

Growth acceleration

"7-day growth acceleration" = growth over the last 7 days − growth over the 7 days before that. A positive number means growth is speeding up, a negative number means it's slowing down — this is a second-order change, not simply a "growth rate ranking."

Milestone speed

"Days to first reach N users" is calculated from the day the extension first appeared in our data collection. If an extension's user count was already above a given threshold the first time we recorded it (for example, if we only started tracking it long after it launched), that means the "first reached" event happened before our data coverage began. In that case we don't fabricate a date — the milestone for that threshold is simply left blank.

SEO Index Pool (Extension Detail indexing policy)

Not every extension's detail page is submitted to search engines for indexing. To enter the initial index pool (Tier 1), an extension must meet all of the following criteria for 7 consecutive days:

  • Current user count ≥ 1,000
  • Review count ≥ 10
  • Last updated within 365 days
  • Page content passes a quality check: a valid functional description, a valid category, at least 30 days of history, and at least one reliably calculable 7/30/90-day growth metric

If an extension already in the index pool has an ordinary metric dip below the threshold, it first enters an approximately 30-day grace period (staying indexed the whole time) rather than being immediately deindexed — this avoids pages flipping in and out of the index due to short-term fluctuations, which is itself harmful to search performance. An extension is removed from the index pool immediately only if it's flagged as delisted/unpublished, or if its data shows a clear anomaly.

Questions this page doesn't answer

We don't make any judgment about an extension's safety, whether it's worth installing, or whether it's better than similar extensions — answering those questions would require information (code audits, permission analysis, UX evaluation) that's outside our current data collection scope, and we won't offer misleading conclusions based on insufficient data.
